# 《無漏》長篇小說專案

版本：0.8

專案狀態：楔子與第一至一百二十二章已有正文，第101至111章為修訂稿，第112至122章為待確認初稿；牧場章群已完成，第二卷續寫從第123章開始，第121至130章細綱已備妥

規劃規模：開放式，可自然延伸至一千二百章以上

文明主軸：界內紀元 → 虛空工業 → 文明艦隊 → 星海掠界 → 諸天戰爭

單章建議字數：二千二百至六千八百字，關鍵章節取高值

## 專案原則

1. 作品聖經管理不變的世界規則。
2. 分卷路線圖管理長期因果與角色弧線。
3. 章卡只管理單章任務，不在章卡內臨時新增重大設定。
4. 正文完成後，立即更新進度、伏筆與連續性台帳。
5. 新設定若與既有設定衝突，先登記於待決事項，確認後再寫入作品聖經。
6. 每章至少推進情節、人物、空間成長三者中的兩項。
7. 爽點必須伴隨代價、選擇或後續影響。

## 設定權限

設定優先級由高至低：

1. 已確認的作品聖經
2. 已確認的科幻文明、科技生命週期與文明債務規格
3. 已確認的分卷／紀元路線圖
4. 已確認的章卡與 Harness 狀態
5. 既有正文
6. AI 臨時提案

同級內容衝突時，以較新的確認版本為準。AI不得自行修改核心鐵律、角色終局或世界真相。

## 每次寫作只提供的上下文 (3-Tier RAG Protocol)

AI 生成正文前，優先建立 `AI_HARNESS/example_request.json` 的當章副本，再執行 `python3 AI_HARNESS/build_context.py <請求檔>`；舊章回溯檢索仍可使用 `python scripts/build_context.py <章號> "<關鍵字>"`：

1. 當章章卡
2. 上三章摘要
3. 當章相關角色資料與世界鐵律
4. 第三層圖譜 (JSON Triplets) 中該實體的歷史連鎖軌跡
5. 尚未回收且即將生效的伏筆
6. 當前資源、傷勢、時間與空間狀態

這套方式能控制上下文長度，徹底消除長篇後期的設定漂移。
